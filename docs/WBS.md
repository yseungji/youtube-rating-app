근거 자료: 프로젝트 제안발표(최종본) PPT, Figma "Page 4 · 5탭 UI"(온보딩·프로필 부가 화면 포함), 11/1 팀 결정 사항

## 진행도 갱신 방법

- 진행도는 `0%` · `25%` · `50%` · `75%` · `100%` 중 하나로 적습니다.
- 담당 칸의 "공동"은 세 명이 함께 하는 작업입니다.
- 자기 작업의 진행도가 바뀌면 그 작업의 PR에 이 파일 수정도 함께 넣습니다. 비고 칸에는 PR 번호(`#6`)나 짧은 메모를 적습니다.
- 남의 줄은 고치지 않습니다. 각자 자기 줄만 고치면 동시에 수정해도 충돌이 적습니다.

## 1. 역할 분담

서로 다른 화면과 데이터를 맡도록 기능 묶음으로 나눴습니다. 같은 파일을 동시에 고치는 일이 줄어 GitHub 충돌이 적습니다.

| 담당 | 맡는 영역 | Figma 화면 | Firebase 담당 |
|---|---|---|---|
| 장주원 | 공통 기반 + 영상 (보고 찾는 기능) | 영상 상세, 카테고리, 탐색, 영상·사용자 검색 결과 | YouTube API 호출(Cloud Functions), 영상 정보 캐시 |
| 김도엽 | 계정 + 프로필 + 관계 (사람과 권한) | 온보딩 A~D, 프로필, 평가한 영상, 팔로워·팔로잉, 설정 | Authentication, Security Rules, 탈퇴 데이터 정리 |
| 유승지 | 평가 + 피드 + 반응 (앱의 핵심 활동) | 피드, 평가하기, 영상 상세의 평가 영역 | 평가·반응 컬렉션, 평점 집계 함수 |

**서로 이어지는 지점**

- 구독 채널·좋아요 영상에 필요한 Google OAuth 토큰: 김도엽이 연동을 만들고(6.3), 유승지가 평가하기 탭에서 사용(5.1)
- 영상 카드·별점·칩 등 공통 컴포넌트: 장주원이 만들고(2.3) 세 명이 함께 사용 ([사용법](UI_COMPONENTS.md))
- 앱 뼈대(하단 5탭)는 장주원이 먼저 만들어 main에 올린 뒤, 각자 담당 탭을 나눠 작업

**참고 사항**

- 최종본 PPT와 Figma가 다른 곳이 있어, 이 표는 Figma와 11/1 팀 결정을 기준으로 작성했습니다.
  - PPT 7번: 피드 반응이 "좋아요·싫어요" → Figma는 좋아요·댓글·공유·나중에 보기
  - PPT 9번: 카테고리가 "베스트 리뷰 1개" → 결정은 1열 목록과 평균 별점, 정렬은 인기순·평점순
- 작업량은 장주원·유승지가 조금 더 많습니다. 조정이 필요하면 4.4 탐색·검색을 김도엽에게 넘기는 것이 가장 자연스럽습니다(사용자 검색이 프로필과 이어짐).
